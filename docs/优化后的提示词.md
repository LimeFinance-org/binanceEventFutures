# 币安事件合约 AI 自动训练与预测系统（优化版提示词）

> 相对原版的改动都用【改】【增】标出，理由见《提示词优化建议.md》。

## 一、项目目标

开发一套专业级、全自动的 Binance Event Contracts AI 训练与预测系统，研究四项任务：

- BTC 未来 10 分钟涨跌、BTC 未来 30 分钟涨跌
- ETH 未来 10 分钟涨跌、ETH 未来 30 分钟涨跌

系统每分钟滚动预测一次，全天 1440 轮，每轮同时预测四项。不要求每次都开仓，没有足够把握时自动跳过。

【改】成功标准分两级，都必须在严格的样本外数据上验证：

1. **盈利标准**：有效开仓信号的胜率，其 95% 置信下界高于盈亏平衡胜率（赔率 80% 时为 1/1.8 = 55.56%）。
2. **研究目标**：有效开仓信号的胜率置信下界达到 70%。

70% 是研究目标而非保证。禁止通过过拟合、数据泄漏或筛选极少量样本制造虚假成绩；达不到时必须如实报告。

【增】"有效"的最低要求（可配置）：信号覆盖率 ≥ 1%、验证期信号数 ≥ 400、去重叠后的有效样本 ≥ 100、
多数验证时段的胜率高于盈亏平衡。

## 二、交易规则（以币安官方规则为准）

【增】本节为事实约束，系统必须遵守：

- 标的 BTCUSDT、ETHUSDT；方向 HIGHER / LOWER；到期前不能平仓。
- 官方入场价为下单后下一秒的指数价格，结算价为到期时刻的指数价格；结算价等于入场价时退还本金。
- **本系统的标签约定**：入场价 = 决策分钟的收盘指数价（等于下一分钟开盘价），到期价 = 10/30 分钟后的收盘指数价。
  这是对秒级结算的近似，系统必须量化该近似的误差（包括入场延迟若干秒时结果的一致率）。
- **赔率**：固定按 80% 计算——猜对时 100 得到 180（净赚 80），猜错时本金归零，平局退还本金。
  支持切换为手工录入实时赔率。
- 事件合约没有 API：系统只输出开仓提示，由人在 App 中手动下单；支持登记真实订单以统计真实结算收益。
- 平台限制（最小下单 5 USDT、每日亏损上限、未到期持仓数上限、单笔上限等）做成可配置项，以 App 交易规则页为准。

## 三、数据系统

使用币安官方可获取的历史行情数据，以分钟级及更高周期数据为基础，不依赖历史秒级数据
（【增】秒级数据仅用于评估标签近似误差）。

允许使用：现货与合约的多周期行情、指数价格、标记价格、溢价指数、成交量与成交行为、资金费率、持仓量与多空比，
以及其他真实可获取且可能有预测价值的数据。

不预先规定必须采用哪些 K 线周期或特征组合，由算法自动研究：哪些数据源、周期、特征有稳定预测价值，
多周期信息如何融合，不同币种和期限是否需要不同特征，哪些特征应当删除。
支持自动特征生成、筛选、组合、重要性评估和消融实验。

所有特征必须严格遵守时间顺序：只使用决策时刻已经收盘、已经发布的数据。
【增】必须有自动化的泄漏检测（例如截断不变性检验），并保证实时计算与离线计算的特征一致。

## 四、自动化模型研究与训练

训练硬件：NVIDIA RTX PRO 6000 Blackwell 96GB、约 22 核 CPU、约 110GB 内存。充分利用 GPU。

不强制指定模型、架构、参数规模或超参数。系统自主研究和比较：传统机器学习模型、深度学习时序模型、
Transformer 类模型、多时间尺度融合模型、多任务学习模型、集成模型及其他有合理依据的方法。
BTC/ETH 与不同期限可以各自选择最佳模型，也可以共享模型或多任务学习，由实验结果决定。

训练系统自动完成：数据处理与特征研究 → 候选模型训练 → 超参数优化 → 多周期融合实验 → 模型比较 →
概率校准 → 样本外验证 → 最佳模型选择 → 结果保存与版本管理。

【改】搜索必须有明确的预算管理（总时间预算、各模型族试验上限、提前剪枝），并且：

- 不能按训练集准确率选模型，优先考虑样本外稳定性、概率质量、实际信号价值和训练效率；
- 复杂模型只有在样本外表现**统计显著**优于简单模型时才会被选中；
- 所有试验完整留痕。

## 五、高胜率信号自动优化

每分钟输出：上涨概率、下跌概率、持平概率、是否发出开仓信号、跳过原因。决策为 HIGHER / LOWER / NO_TRADE。

由算法自动优化置信度阈值、信号筛选条件、市场状态过滤、集成权重、各任务的决策规则，以及覆盖率与胜率的平衡。
所有参数选择在训练与验证阶段完成，并在独立测试集中检验。

【改】不允许反复利用最终测试集寻找有利参数：系统必须维护测试集访问台账，同一测试窗口默认只评估一次，
重复评估必须显式强制并在报告中标注。

必须报告真实样本数量、覆盖率、置信区间（要处理重叠样本的相关性）和不同市场环境下的稳定性。

## 六、每分钟滚动预测与连续开仓

允许连续开仓（之前的合约未到期也可以继续发出信号），但必须有独立于预测模型的全局风险管理器，统一考虑：
所有未到期合约、BTC 与 ETH 的相关性、不同期限的持仓重叠、连续同向开仓的风险集中、单笔上限、
总风险预算、每日亏损上限、平台限制。

【改】风控额度是人设定的上限，算法只能在上限之内运行，不能为了改善回测而放宽。
历史模拟和压力测试用于评估这些上限下的回撤与亏损概率。

只有预测质量、赔率、预期收益和风险审批全部达标时，才生成可执行的开仓提示。
使用手工赔率模式且赔率缺失或过期时，只输出研究预测。

## 七、严格训练与回测

使用专业的金融时间序列验证方法：Walk-Forward、时间序列交叉验证、Purging 与 Embargo、独立样本外测试、
概率校准、过拟合检测、特征泄漏检测、重叠预测样本的相关性处理、不同市场状态的稳定性分析、统计置信区间。

回测必须模拟真实的每分钟决策过程，不能使用未来数据。目标是可重复的样本外优势，而不是某一次历史回测的高分。

必须区分并分别报告：方向预测准确率（全部预测）、有效开仓信号胜率、固定赔率下的预期收益、模拟收益、真实订单结算收益。
【改】没有历史真实赔率，所有收益回测都必须标注为"固定赔率模拟"，不得称为真实收益。

## 八、中文 Web 管理系统与自动化运行

提供完整的中文 Web 管理界面：历史数据管理、训练任务管理、模型搜索进度、GPU 资源监控、模型排行榜、
最佳特征与周期组合、样本外回测结果、实时四项预测、开仓信号与跳过原因、风险预算与未到期合约、
历史信号统计、模型版本管理与回退、训练异常恢复、数据及模型自动更新。

保存所有预测记录（包括未开仓的）。实时预测与 GPU 训练相互隔离，训练不能造成预测超时。支持长期运行和持续迭代。
【增】模型自动更新采用"冠军/挑战者"机制：新版本只有在同一样本外窗口上优于线上版本才会自动上线。

## 九、开发原则

1. 不预先限制模型和特征的合理搜索空间，不人为指定最佳周期组合，由严谨实验选择方案。
2. 数据与回测的真实性优先，严格防止未来数据泄漏。
3. 自动优化过程保留完整实验记录。
4. 复杂模型必须证明优于简单模型。
5. 效果不达标时允许继续研究，但不能伪造结果。
6. 所有核心模块必须有可运行代码和自动测试。

## 十、交付要求

完整工程：数据采集与存储、自动特征工程、多周期融合、自动模型搜索与训练、概率校准与信号优化、
严格样本外回测、连续开仓风险管理、每分钟实时预测服务、中文 Web 控制台、模型自动更新与版本回退；
以及完整源代码、部署脚本、依赖环境、自动测试、配置文件和使用说明。

先设计整体架构（实验搜索空间、计算资源分配、样本外验证、模型选择机制），再按可验证的阶段逐步实现。

**我只规定预测目标、硬件资源、交易规则与真实性要求。具体采用哪些数据周期、特征、模型架构、超参数及融合方式，
由自动化训练系统通过严格实验自主选择。**
